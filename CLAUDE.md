# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Static marketing/legal site for **bugalgo.com** — a product company shipping mobile and desktop apps (AçıkEczane, Sınav Koçu, Lumnos, Opero). The repo is named `yenererdolu.github.io` but the published domain is `bugalgo.com` (see `public/CNAME`). Built with Astro 5 (static output) + React 19 islands + Tailwind CSS 4. Default UI language is Turkish; content is bilingual (TR/EN) at runtime.

## Commands

```bash
npm install
npm run dev        # astro dev — http://localhost:4321
npm run build      # astro build → dist/
npm run preview    # serve the built dist/ (use this to verify before pushing)
```

There is no test suite, linter, or typecheck script. There is no PR preview environment — verification is always `npm run build && npm run preview` locally.

## Deployment

`git push` to `main` triggers `.github/workflows/deploy.yml`, which builds and deploys `dist/` to GitHub Pages. `dist/`, `node_modules/`, and `.astro/` are gitignored — only `src/` and `public/` are sources of truth. CNAME and verification files (`app-ads.txt`, `google6a5136bdf9069662.html`) live in `public/` and Astro copies them verbatim into `dist/`. See `DEPLOYMENT.md` for the GitHub Pages source configuration and rollback options.

## Architecture

**Astro page = thin SEO shell; React island = all UI.** Every file in `src/pages/**/*.astro` wraps `src/layouts/Base.astro` (which renders `<head>` meta/OG/canonical tags) around a single React component loaded with `client:load`. Astro frontmatter sets per-page title/description/canonical; the React component renders everything visible. Each `.astro` page imports `@/styles.css`.

**`AppShell` is the React root for every page.** Components like `HomePage`, `ProductDetailPage`, and `LegalPage` wrap their content in `AppShell`, which provides `LanguageProvider` (TR/EN context) plus `GradientBackdrop`, `SiteHeader`, and `SiteFooter`. Any new page-level React component must render inside `AppShell` to get the header/footer and language context.

**Two parallel sources of product data — keep them in sync:**
- `src/lib/products.ts` — structural metadata: the `ProductSlug` union, icon/gradient/screenshots/video, `platform` ("mobile" default → store badges; "desktop" → demo/contact CTA), and `STORE_URLS` (App Store / Google Play links).
- `src/i18n/dictionaries.ts` — all user-facing copy in `tr` and `en`, including per-product `name`/`tag`/`short`/`long`/`features`. Consumed via `useT()` / `useLanguage()` from `LanguageProvider`.

Adding or changing a product means editing **both** files, and `ProductSlug` must stay consistent across `products.ts`, `dictionaries.ts`, and `src/pages/products/[slug].astro`'s `getStaticPaths` slug list.

**Routing.** Product landing pages are generated by `src/pages/products/[slug].astro` (`getStaticPaths` over the slug list). Per-product **legal/support pages are NOT dynamic** — they are hand-written static `.astro` files under `src/pages/products/<slug>/{privacy,terms,support}.astro` (Lumnos also has `account-deletion.astro` + an `account-delete.astro` alias). Each renders the shared `LegalPage` component with breadcrumbs and inline HTML content (these legal docs are bespoke per product, often EN-only, and not stored in the i18n dictionaries).

## Critical: do not break indexed URLs

These paths are indexed by Google Search Console and referenced in live App Store / Google Play listings. They must keep resolving (note the trailing-slash directory format, set by `build.format: "directory"`):

```
/products/acikeczane/{,privacy/,terms/,support/}
/products/sinavkocu/{,privacy/,terms/,support/}
/products/lumnos/{,privacy/,terms/,support/,account-deletion/}
/app-ads.txt
/google6a5136bdf9069662.html
```

Renaming a slug, removing a legal page, or changing the URL format is a breaking change — preserve the path (add a redirect/alias if a page must move).

## Conventions

- Import alias `@/*` → `src/*` (configured in `tsconfig.json`).
- TypeScript strict mode (extends `astro/tsconfigs/strict`).
- Tailwind 4 is loaded via the `@tailwindcss/vite` plugin; design tokens and custom utilities (`glass-panel`, `shadow-soft`, etc.) live in `src/styles.css`, not a `tailwind.config`.
- `legacy/` is the archived pre-Astro static HTML site, kept only as a rollback reference — do not edit it for live changes.
- Commit messages in history use Conventional Commits (`feat:`, `fix:`, `chore:`), frequently with Turkish descriptions.
